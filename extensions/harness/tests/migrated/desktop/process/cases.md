The 26 `port` rows of batch 4's first lane (catalogue areas Desktop application, Command line and Core engine: single instance, links handed over at launch, window placement, preferences persistence, build identity and installer inputs), each replaced by one row per reference case, following core `documentation/future/harness/testing/04-test-migration.md` sections 2 and 5. Written by lane S2-C3a; the integrator publishes the counts.

- `id` is the parent row's id with a `.cN` suffix. `source` is the reference path at the pinned tag and the case, described in this crate's own words.
- `target` names the Rust test in this crate (`migrated-desktop-process::<module>::<test>`) or, for `covered`, the existing shell test.
- `state`: `passing` (the test runs and passes); `ledger` (the harness behaves differently: the test asserting the reference behaviour carries `#[ignore = "parity ledger: …"]`, or, where no test can express it, `note` states the difference and where it lives; a target listed on a ledger row asserts the part that holds); `tour` (needs a display: not asserted, recorded as a state on `extensions/harness/tests/tour/states.txt` and checked by a person, `note` names the state).
- Generated or table-driven reference cases are one row per generator where marked `(generated)`.
